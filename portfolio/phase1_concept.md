I designed a batch data backend for hourly taxi demand and fare forecasting using official NYC TLC yellow-taxi Parquet files (timestamped, millions of rows per month). A monthly Airflow DAG ingests the newest published month into MinIO (raw layer) with size, schema and checksum verification. A quarterly DAG, matching the ML application's refresh cycle, runs Spark to validate, deduplicate and clean the data, writing accepted and rejected rows (with reasons) as partitioned Parquet, then aggregates by pickup hour and taxi zone and builds leakage-free forecasting features. Results are published atomically to PostgreSQL, where a read-only role serves the ML application.
Every component is an isolated Docker Compose microservice defined as code and versioned in Git. Reliability comes from retries, health checks, idempotent writes and reconciliation checks; scalability from partitioned Parquet and additional Spark workers; maintainability from environment-based configuration and unit tests. Security uses least-privilege database and object-store accounts, localhost-only ports and lineage records. Advantages: simple, reproducible, transparent data quality. Disadvantages: single-node local deployment, no TLS or streaming, and latency of one quarter by design.
